۰ چه چیزهایی لازم داری

چیزتوضیح
سرور مجازی (VPS)اوبونتو ۲۲.۰۴ یا ۲۴.۰۴ — حداقل ۲ گیگ رم و ۲۰ گیگ فضا. با ۱ گیگ، مرورگر وسط کار کشته می‌شود.
دسترسی rootیوزر root و رمزش، یا یک یوزر با sudo.
حساب مفیدنام کاربری و رمز ایزی‌تریدر.
برنامه‌ی SSHروی گوشی: Termius یا JuiceSSH.
چرا سرور ایرانی

سایت مفید از بیرون ایران معمولاً باز نمی‌شود. سرور را ایران بگیر، وگرنه ربات مدام خطای «سایت در دسترس نیست» می‌دهد.

۱ وصل شدن به سرور

از برنامه‌ی SSH گوشی وصل شو — به‌جای IP-سرور آی‌پی خودت را بگذار. از اینجا به بعد همه‌ی دستورها داخل همین ترمینال زده می‌شوند.

ssh root@IP-سرور

۲ تنظیم ساعت سرور

این مرحله را رد نکن

زمان‌بندی سفارش‌ها روی ساعت سیستم است. ساعتِ عقب یعنی سفارشِ دیر.

timedatectl set-timezone Asia/Tehran
timedatectl set-ntp true
timedatectl

خروجی باید ساعت درست تهران و System clock synchronized: yes را نشان بدهد.

۳ نصب بسته‌های سیستمی

apt update
apt install -y python3 python3-venv python3-pip git tzdata

سه بسته‌ی مخصوص «ورود دستی»

این‌ها آن صفحه‌ای را ممکن می‌کنند که مرورگرِ داخل سرور را روی گوشی‌ات نشان می‌دهد تا خودت رمز و کد پیامکی را وارد کنی:

apt install -y xvfb x11vnc novnc
نصبشان کن

بدون این سه بسته بقیه‌ی پنل کار می‌کند، ولی صفحه‌ی «ورود دستی» بالا نمی‌آید. روزی که رمزت عوض شود یا کارگزاری کد پیامکی بخواهد، بدون آن صفحه گیر می‌کنی.

۴ گرفتن کد پروژه

mkdir -p /opt/mofid-bot
git clone -b claude/relaxed-cori-6p65ae https://github.com/aga074974-cmd/Bot-tread.git /opt/mofid-bot
cd /opt/mofid-bot

claude/relaxed-cori-6p65ae اسم شاخه‌ای است که تغییرات روی آن انجام می‌شود؛ هر آپدیت جدید روی همین می‌آید.

۵ محیط پایتون

python3 -m venv /opt/mofid-bot/.venv
/opt/mofid-bot/.venv/bin/pip install --upgrade pip
/opt/mofid-bot/.venv/bin/pip install -r /opt/mofid-bot/requirements.txt

اگر pip وسط دانلود قطع شد، همان دستور را دوباره بزن — ادامه را از همان‌جا می‌گیرد. اگر باز هم نشد، یک میرور PyPI ایرانی روی سرور تنظیم کن.

۶ نصب مرورگر

ربات یک مرورگر واقعی (Chromium) را کنترل می‌کند. آن را در مسیر مشترک می‌گذاریم تا کاربرِ سرویس هم پیدایش کند:

export PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers
/opt/mofid-bot/.venv/bin/playwright install --with-deps chromium

اگر دانلود با خطای ۴۰۳ خورد، اول این را بزن و بعد دستور بالا را تکرار کن:

export PLAYWRIGHT_DOWNLOAD_HOST=https://cdn.npmmirror.com/binaries/playwright

۷ فایل تنظیمات .env

cp /opt/mofid-bot/.env.example /opt/mofid-bot/.env
nano /opt/mofid-bot/.env

ذخیره: Ctrl+O بعد Enter — خروج: Ctrl+X.

کلیدچه بگذاری
MOFID_USERNAMEنام کاربری ایزی‌تریدر
MOFID_PASSWORDرمز ایزی‌تریدر
PANEL_PASSWORDرمزی که خودت می‌سازی، برای ورود به پنل. طولانی بگذار.
SESSION_SECRETیک رشته‌ی تصادفی بلند. خالی بماند، با هر ری‌استارت از پنل بیرون می‌افتی.
DRY_RUNفعلاً true — حالت تمرین، سفارش واقعی نمی‌رود.
HEADLESStrue بماند.

برای ساختن SESSION_SECRET، این را بزن و خروجی‌اش را کپی کن:

openssl rand -hex 32

بقیه‌ی کلیدها یعنی چه

  • GRACE_PERIOD_SECONDS=120 — اگر سرور ری‌استارت شد و سفارش تا این چند ثانیه عقب افتاد، باز هم اجرا می‌شود؛ بیشتر از آن «اجرا نشد» می‌خورد.
  • RETRY_DEADLINE_SECONDS=90 — بعد از این چند ثانیه از زمان سفارش، تلاش تازه شروع نمی‌شود. سفارشی که ۸ دقیقه دیر برود، دیگر همان سفارش نیست.
  • MAX_RETRIES=5 — حداکثر تعداد تلاش.
  • SCREENSHOT_RETENTION_DAYS=3 — عکس‌های هر سفارش بعد از ۳ روز پاک می‌شوند.
  • ORDER_HISTORY_RETENTION_DAYS=30 — سفارش‌های قدیمی‌تر از ۳۰ روز از تاریخچه پاک می‌شوند.
  • STORAGE_STATE_PATH — جایی که نشستِ ورود ذخیره می‌شود.

اگر novnc را جای دیگری نصب کردی (پیش‌فرض /usr/share/novnc)، این خط را هم اضافه کن:

NOVNC_DIR=/مسیر/واقعی/novnc
مواظب املا باش

فقط true و false شناخته می‌شوند. اگر fasle بنویسی، ربات آن را true می‌خواند (یعنی حالت تمرین) و یک هشدار در لاگ می‌نویسد. غلط املایی سفارش واقعیِ ناخواسته نمی‌سازد، ولی ممکن است فکر کنی زنده‌ای و نباشی — بعد از تغییر این خط لاگ را چک کن.

۸ کاربر و دسترسی‌ها

سرویس با یک کاربر بی‌دسترسی اجرا می‌شود، نه با root:

useradd -r -s /usr/sbin/nologin mofidbot
mkdir -p /opt/mofid-bot/logs
chown -R mofidbot:mofidbot /opt/mofid-bot /opt/pw-browsers
chmod 600 /opt/mofid-bot/.env
چرا مالکش mofidbot باشد

.env رمز حساب کارگزاری‌ات را دارد؛ 600 یعنی فقط صاحبش بخواندش. مالکش هم باید mofidbot باشد، چون وقتی از پنل تیک «ذخیره برای دفعات بعد» را می‌زنی، خودِ پنل این فایل را بازنویسی می‌کند.

۹ سرویس دائمی

با این کار پنل با بستن SSH قطع نمی‌شود و بعد از ری‌استارت سرور هم خودش بالا می‌آید.

cp /opt/mofid-bot/systemd/mofid-panel.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now mofid-panel
systemctl status mofid-panel

باید active (running) باشد. برای دیدن لاگ زنده (خروج با Ctrl+C):

journalctl -u mofid-panel -f
سرویس دوم را نصب نکن

mofid-bot.service مالِ حالت قدیمیِ orders.yaml است. اگر از پنل استفاده می‌کنی نصبش نکن — هر دو با هم یعنی هر سفارش دو بار.

۱۰ باز کردن پورت

ufw allow 8080/tcp
ufw status

اگر هاستت پنل فایروال جدا دارد، از همان‌جا هم پورت 8080 را باز کن.

۱۱ اولین ورود به پنل

از مرورگر گوشی برو به این آدرس و رمزی که در PANEL_PASSWORD گذاشتی را وارد کن:

http://IP-سرور:8080

باید صفحه‌ی «پنل ربات» با ربات متحرکِ بالای صفحه بیاید.

۱۲ ورود به حساب مفید

وسط هدر پنل یک چراغ گرد هست: قرمز یعنی نشستِ ورود معتبر نیست (اولین بار همین‌طور است)، سبز یعنی ربات وارد حساب هست و می‌تواند سفارش بفرستد.

یک بار روی چراغ بزن؛ خودش با نام‌کاربری/رمزِ .env تلاش می‌کند. اگر نشد (کد پیامکی، کپچا، رمز عوض‌شده) زیر چراغ لینک «ورود دستی» هست:

  1. روی «ورود دستی» بزن.
  2. مرورگرِ داخل سرور را روی گوشی‌ات می‌بینی — همان صفحه‌ی ورود مفید.
  3. خودت نام کاربری، رمز و کد پیامکی را وارد کن.
  4. به‌محض ورود، صفحه خودش می‌بندد و چراغ سبز می‌شود.
  5. وقتی از صفحه بیرون بروی، مرورگر سرور هم خودکار بسته می‌شود.
دو کار که ربات هرگز نمی‌کند

ربات کپچا حل نمی‌کند و «اقرارنامه و بیانیه ریسک» را امضا نمی‌کند. این دو کارِ خودِ صاحب حساب است — از همین صفحه‌ی ورود دستی انجامشان بده.

بعد از ورود موفق، نشست در auth_state.json ذخیره می‌شود. اگر رمزت را عوض کردی، این فایل را پاک کن تا از نو وارد شود:

rm -f /opt/mofid-bot/auth_state.json

۱۳ تست، بعد حالت واقعی

تا وقتی DRY_RUN=true است، ربات واقعاً وارد می‌شود، نماد را باز می‌کند و فرم را پر می‌کند، ولی دکمه‌ی نهایی ارسال را نمی‌زند — یعنی تست بی‌خطر.

  1. در ساعت معاملات بازار یک سفارش تمرینی برای چند دقیقه‌ی بعد ثبت کن.
  2. وقتی وضعیتش عوض شد، کنارش آیکون ▶ می‌آید — بزن تا گالری عکس‌ها باز شود.
  3. عکس ..._quantity_filled را نگاه کن: باید تعداد را درست پر کرده باشد.
  4. اگر جایی گیر کرد، آخرین عکس نشان می‌دهد کجا و فایل page.html نشان می‌دهد چرا. هر دو از همان گالری قابل دانلودند — بفرستشان تا اصلاح شود.
حتماً در ساعت بازار تست کن

شب، خودِ اپ می‌نویسد «خارج از ساعت معاملات!» و ممکن است کیبورد عددی اصلاً باز نشود؛ آن‌وقت خطای طبیعی را با خرابیِ ربات اشتباه می‌گیری.

فقط وقتی عکس‌ها درست بودند، DRY_RUN=true را به false عوض کن و سرویس را ری‌استارت کن:

nano /opt/mofid-bot/.env
systemctl restart mofid-panel

به‌روزرسانی روزمره

هر وقت تغییر جدیدی آمد، همین سه خط:

cd /opt/mofid-bot
git pull origin claude/relaxed-cori-6p65ae
systemctl restart mofid-panel

اگر git pull گفت dubious ownership، یک‌بار این را بزن و دوباره امتحان کن:

git config --global --add safe.directory /opt/mofid-bot

اگر آپدیت کتابخانه‌ی جدیدی داشت (به‌ندرت)، بعد از git pull این را هم بزن:

/opt/mofid-bot/.venv/bin/pip install -r /opt/mofid-bot/requirements.txt

کار روزمره با پنل

  • ثبت سفارش: نماد، خرید/فروش، تعداد، نوع سفارش، تاریخ و ساعت.
  • زمان باید دست‌کم یک دقیقه جلوتر از الان باشد. اگر گذشته باشد پیام «وقت سفارش گذشته» می‌آید و آنچه نوشته بودی پاک نمی‌شود — فقط ساعت را عوض کن. این قید فقط برای امروز است.
  • تعداد خالی: کنار عنوان «تعداد» یک ! قرمز و «تعداد را وارد کنید» می‌آید و با شروع تایپ محو می‌شود.
  • سفارش‌های در انتظار همیشه بالای صفحه می‌مانند تا بتوانی لغوشان کنی.
  • لغو: سفارشِ لغوشده کلاً حذف می‌شود و در تاریخچه نمی‌ماند.
  • تاریخچه: فقط سفارش‌های تمام‌شده — سه‌تای آخر در صفحه‌ی اصلی، بقیه در /history.
  • خطا: روی وضعیت «ناموفق» بزن تا پیام فارسی سه ثانیه ظاهر شود.
  • عکس‌ها: آیکون ▶ کنار وضعیت → گالری، قابل دیدن و دانلود.
  • خروج از پنل: آدرس /logout.

نکات ریسک — این‌ها را حتماً بخوان

API رسمی نیست

ربات دقیقاً کاری را می‌کند که تو با انگشت روی سایت می‌کنی، فقط خودکار. استفاده‌ی خودکار از اپ ریتیل ممکن است با قوانین کارگزاری مفید در تناقض باشد و در بدترین حالت به مسدود شدن حساب برسد. مسئولیتش با توست.

  • قبل از هر عددی نماد چک می‌شود. اگر نام روی تیکت با نمادی که خواسته‌ای یکی نبود، سفارش متوقف می‌شود — سفارشِ درست روی نمادِ اشتباه بدترین اتفاق ممکن است.
  • تعداد بعد از پر شدن دوباره خوانده می‌شود و اگر با خواسته‌ات یکی نبود، ارسال نمی‌شود.
  • پیام موفقیت هنوز روی یک سفارش واقعی تأیید نشده. اگر ربات گفت آن را نشناخت، الزاماً یعنی سفارش ثبت نشده نیست — خودت در اپ مفید چک کن.
  • پنل روی HTTP است، نه HTTPS. رمز پنل رمزنگاری‌نشده رد می‌شود؛ رمز طولانی و بی‌ربط بگذار و اگر می‌توانی پورت را فقط به آی‌پی خودت باز کن.
  • هر کسی رمز پنل را داشته باشد می‌تواند از حساب تو سفارش بفرستد.
  • پنل و حالت orders.yaml دو سیستم جدا هستند؛ هم‌زمان اجرایشان نکن.
